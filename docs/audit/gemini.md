# Prompton サイト点検報告（再点検版・2026-11-10）

対象リポジトリ：`morohami/prompton`（`main` ブランチ、コミット `e685e7a`）および公開サイト <https://morohami.github.io/prompton/>。
コードの変更・コミット・プッシュは一切行っていません。

## 点検の前提と確かめ方

- **前提（`HANDOFF.md` の決まり）**：作品単位の呼称は小文字の `prompton`（プロンプト本文や欄名のみ `prompt`）、サイト文言に特定の AI ベンダー名を出さない（モデル選択肢と機能上の「↗ Open in Claude.ai」ボタンのみ例外、新規既定モデルは `'AI'`）、作品プレビュー iframe には `allow-same-origin` を付けない、PAT 欄は iOS 対策のため `type="text"`＋`-webkit-text-security` マスク維持、ルート `.nojekyll` は削除しない。
- **問題なかった点**：
  - `manifest.json` 全 28 件の本体ファイル（フラット HTML 23 件・フォルダ `index.html` 3 件・Markdown 2 件）、過去版 HTML（`p003_v1〜v3`、`p1779734355097_v1〜v2`）、`thumb` 指定済み 27 件の `.jpg` はすべて実在。サムネや `p/` 側の孤立ファイルもなし（`htmls/_md_demo.md` のみ孤立）。
  - `i18n/en.json` と `i18n/ja.json` のキー集合（112 キー）は完全一致しており、片方だけのキー抜けはなし。
  - `.nojekyll` の存在、PAT 欄の `type="text"`＋マスク実装、全プレビュー iframe に `allow-same-origin` が付いていないことを確認済み。
- **確かめた方法の表記**：ローカル静的サーバー＋ヘッドレス Chrome（Playwright）または公開サイトで実際に画面・通信・DOM を確認したものは「実際に開いた」、スクリプトで全件照合したものは「コード・データ照合」、実動作を再現していないものは「コードを読んだだけ（未）」と記載しています。

## 先に直すべき上位5件

1. **スマホ詳細画面の操作不能とスマホ／PC の検索不具合を直す（#1・#2）**
   スマホ詳細画面で `.preview-overlay` に `pointer-events: auto` がなく「全画面」「別タブで開く」が一切押せないうえ、スマホ・タブレット（`≤900px`）で検索欄が完全に表示されず、PC でも一覧絞り込みが動いていないため、閲覧・検索の基本体験として最優先で直すべきです。
2. **GitHub PAT の同一オリジン露出経路をふさぐ（#3・#4）**
   詳細 iframe から `allow-popups-to-escape-sandbox` を外し、PAT を `localStorage` に常駐させない（`sessionStorage` 化や都度入力、単体表示の別オリジン分離）ことで、同オリジン他サイトや作品内の外部スクリプトからトークンを読まれるリスクを解消します。
3. **訪問者へのオーナー UI 誤表示と unlisted 作品の露出を止める（#5）**
   `canSaveNewVersion` を `isOwner()` 判定のみにし、「Made for you」行に `.filter(isListed)` を足すだけの小さな修正で、訪問者に「新バージョンを保存」が出る問題と `prompton-handoff`・`_folder_demo` が見えている問題を同時に止められます。
4. **ダウンロード・フォーク・別タブ表示で空ファイルや古い版・404 になる不具合をまとめて直す（#6・#7・#10・#11）**
   東京今昔マップの v2 上書き問題、フォルダ型フォーク時の 0 バイト出力、`openStandaloneLink` のフォルダ型・md 型 404、フォルダ型での新バージョン保存ボタン露出はすべて「フラット単一 HTML 前提の残り」なので、`promptHtmlPath()` とレイアウト判定で一括して直せます。
5. **全作品 HTML の `localStorage` 保存をやめ、初期ロードの HTML 全件待ちも外す（#8・#20）**
   `promptshare_v4`（約 5.2MB）がブラウザの `localStorage` 5MB 上限寸前でいつ書き込み失敗してもおかしくない状態であり、かつ初回描画前の全 HTML 取得待ちが低速回線で約 10 秒の遅延を生んでいるため、`manifest.json` のみで即描画・保存する形に改めると安定性と表示速度が一気に改善します。
